# MacroCore

โปรแกรมอัดและเล่นเมาส์/คีย์บอร์ดสำหรับ Windows มีทั้งหน้าต่าง GUI และ command line
ใช้ Python standard library: `ctypes` สำหรับ Win32 hooks / SendInput และ `tkinter` สำหรับ GUI

## เริ่มใช้งาน

ดับเบิลคลิก **`dist\MacroCore.exe`** เพื่อเปิดหน้าต่างโปรแกรมได้เลย ไม่มีหน้าต่าง command line
ไฟล์นี้รวม Python และ Tcl/Tk แล้ว สามารถคัดลอกเฉพาะ `.exe` ไปใช้บน Windows x64 ได้โดยไม่ต้องติดตั้ง Python แยก
การแพ็ก `.exe` ช่วยให้เปิดใช้งานสะดวกขึ้น ตัวโปรแกรมยังใช้แกน Python เดิม

[ดาวน์โหลด MacroCore.exe สำหรับ Windows x64](https://github.com/vacharapolndkku/OS-MiniProject/raw/refs/heads/main/dist/MacroCore.exe)

repository เก็บ `.exe` รุ่นล่าสุดที่ `dist/MacroCore.exe` พร้อมใช้ หากแก้ source ต้อง build ใหม่ตามหัวข้อด้านล่าง
build cache, build environment และไฟล์อื่นใน `dist` ถูกยกเว้นจาก Git ด้วย `.gitignore`
`macro.json` และ drift log เป็นข้อมูลที่บันทึกในเครื่อง จึงไม่อัปโหลดไป repository; อัดมาโครใหม่หรือเลือกเปิดไฟล์ของตัวเองได้

หากรันจาก source ต้องมี Windows และ Python 3.10 ขึ้นไป พร้อม Tcl/Tk (`tkinter`) ไม่ต้องติดตั้งแพ็กเกจผ่าน pip:

```powershell
python macro_gui.py
```

1. กด **อัด / F9** หน้าต่างหลักจะย่อ เหลือแถบสถานะเล็กที่มุมบนขวาของจอหลัก แล้วทำงานที่ต้องการบันทึก
2. กด **F9 หรือ F11** เพื่อหยุดอัด หน้าต่างหลักจะกลับมา
3. กด **บันทึกเป็น / F8** เพื่อเลือกไฟล์ JSON
4. จัดหน้าต่างปลายทางให้เหมือนตอนอัด ตั้งความเร็วและจำนวนรอบ แล้วกด **เล่น / F10**
5. GUI รอ 3 วินาทีก่อนเล่นเป็นค่าเริ่มต้น เพื่อให้สลับไปหน้าต่างปลายทางได้ ปรับเวลานี้ได้

การอัดใหม่แทนที่มาโครในหน่วยความจำ GUI จะถามเรื่องบันทึกก่อนแทนที่งานที่ยังไม่ได้บันทึก
การเปิดไฟล์ผิดรูปแบบจะไม่แทนที่มาโครปัจจุบัน

หน้าต่างหลักแสดงเฉพาะปุ่มควบคุม ไฟล์ปัจจุบัน และสรุปการเล่น เปิด **ตั้งค่า…** เพื่อปรับความเร็ว/จำนวนรอบ
ตัวเลือก Mouse rate และ timer อยู่ใน **ตัวเลือกขั้นสูง** ส่วน log เปิดจาก **ประวัติ**
หน้าต่างตั้งค่าและประวัติจะปิดก่อนเริ่มอัด/เล่น เพื่อเหลือพื้นที่ให้แอปปลายทาง

แถบสถานะแสดงเวลาและปุ่มลัดหยุด คลิกเมาส์ผ่านไปยังแอปด้านหลังได้ และไม่รับโฟกัสคีย์บอร์ด
หยุดด้วย F9/F11 ขณะอัด หรือ F10/F11 ขณะเล่น หากต้องการซ่อนทั้งหมด ปิด **แสดงแถบสถานะเล็กที่มุมจอ** ในตั้งค่า
หากปิด **ย่อหน้าต่างเมื่อเริ่มอัด / เล่น** หน้าต่างหลักจะยังแสดงอยู่

| ปุ่ม | การทำงาน |
| --- | --- |
| F9 | เริ่ม / หยุดอัด |
| F10 | เริ่ม / หยุดเล่น |
| F11 | หยุดอัดหรือเล่น รวมถึงช่วงนับถอยหลัง |
| F8 | บันทึกไฟล์ (GUI ให้เลือกชื่อไฟล์) |
| F12 | ปิดโปรแกรม |

Hotkey ทำงานทั่วระบบระหว่างเปิดโปรแกรมและจะไม่ถูกส่งต่อไปแอปปลายทาง
กดค้างจะสั่งเพียงครั้งเดียวต่อการกด หาก GUI ปิดขณะมีงานที่ยังไม่ได้บันทึก จะถามก่อนทิ้งงาน
ควรเปิดโปรแกรมเพียงหนึ่ง instance เพื่อไม่ให้ hooks แย่ง hotkey กัน

## ตั้งค่าการเล่น

- **ความเร็ว:** `0.5` = ช้าลงครึ่งหนึ่ง, `2` = เร็วสองเท่า ต้องมากกว่า 0
- **จำนวนรอบ / วนต่อเนื่อง:** เลือกจำนวนรอบ หรือวนจนกดหยุด
- **รอก่อนเล่น / พักระหว่างรอบ:** เวลาเป็นวินาที ต้องไม่ติดลบ
- **Mouse rate:** ค่าเริ่มต้น `250 Hz` เก็บตำแหน่งสุดท้ายในแต่ละช่วงเวลาระหว่าง move ที่ต่อกัน เพื่อลดภาระ replay โดยเก็บ event คลิก ปุ่ม และล้อเมาส์ทุกตัว ใช้ `0` เพื่อเล่น move เดิมทุกจุด หากต้องการเส้นทางลากละเอียด
- **จับเวลาละเอียด:** ใช้การรอแบบ hybrid ช่วงท้ายมี busy-wait จึงใช้ CPU เพิ่มขึ้น ปิดเพื่อใช้การรอแบบ sleep
- **Timer resolution 1 ms:** ขอความละเอียด timer จาก Windows ระหว่างเล่น และคืนเมื่อจบ ไม่รับประกันว่าทุก event จะตรงเวลา 1 ms

เมื่อหยุดหรือเล่นจบ โปรแกรมจะพยายามปล่อยปุ่มที่ตัว replay กดค้างไว้ รวมถึงระหว่างรอบ
หาก Windows ปฏิเสธ SendInput จะหยุด replay และแจ้งใน log; การปล่อยปุ่มก็อาจถูกปฏิเสธได้เช่นกัน
แอปปลายทางที่เปิดด้วยสิทธิ์สูงกว่าโปรแกรมอาจรับ input ไม่ได้

## Command line

ยังใช้คำสั่งเดิมได้ และเปิด GUI พร้อมโหลดมาโครได้เช่นกัน:

```powershell
python macrocore.py
python macrocore.py --load --file macro.json --speed 1.5 --loop 5 --delay 3 --loop-delay 1
python macro_gui.py --load --file macro.json
python macrocore.py --load --mouse-hz 0 --wait sleep
```

`--loop 0` คือวนไม่สิ้นสุด, `--timer-1ms` เปิดคำขอ timer resolution, `--help` แสดงตัวเลือกทั้งหมด
CLI ไม่รอก่อนเล่นโดยค่าเริ่มต้น และ F8 บันทึกตรงไปยัง `--file`
ตัว `.exe` รับตัวเลือกของ GUI เหมือนกัน เช่น `MacroCore.exe --load --file "C:\path\macro.json"`
ไฟล์มาโครเลือกเปิด/บันทึกผ่านหน้าต่างได้ ส่วน drift log ค่าเริ่มต้นอยู่ใน working directory ที่เปิดโปรแกรม

ไฟล์ JSON ยังใช้รูปแบบ list ของ event เดิม เปิด `macro.json` ที่มีอยู่ได้
การบันทึกเขียนไฟล์ชั่วคราวในโฟลเดอร์เดียวกันก่อนแทนที่ไฟล์จริง เพื่อลดโอกาสไฟล์เดิมเสียหายเมื่อเขียนไม่สำเร็จ

## Drift log และการตรวจสอบ

เมื่อเล่นจบหรือหยุด จะเขียน `drift_log.csv` (เปลี่ยนด้วย `--drift-log`) และแสดง mean / p95 / max
ค่าดังกล่าววัดเวลาก่อนเรียก SendInput ไม่ใช่เวลาที่แอปปลายทางประมวลผล input เสร็จ
เก็บ log สูงสุด 100,000 event ล่าสุด เพื่อจำกัดหน่วยความจำระหว่างวนเล่นนาน ๆ; index ยังคงอ้างอิงลำดับจริงทั้ง run
ไฟล์ log จะถูกเขียนทับในแต่ละ run ที่มี event ส่งสำเร็จ และห้ามตั้งชื่อเดียวกับไฟล์มาโคร

```powershell
python -m unittest -v
```

ชุดทดสอบจำลอง SendInput และไม่ติดตั้ง hooks จึงไม่ขยับเมาส์หรือพิมพ์จริง
ชุด GUI ใช้หน้าต่างซ่อน และจะ skip หาก environment ไม่มี Tcl/Tk ที่ใช้งานได้

ตรวจแล้วกับ Python 3.14 บนเครื่องนี้: core 17 กรณี และ GUI 14 กรณีผ่าน รวม 31 กรณี
ตรวจติดตั้งและถอด Win32 hooks จริงได้สำเร็จ โดยไม่ได้เริ่มอัดหรือส่ง input
มาโครตัวอย่างเดิมมี move 2,572 event; การเตรียมเล่นที่ 1x / 250 Hz เหลือ 234 event
ยังไม่ได้วัด drift หลังปรับจากการเล่นจริงหรือทดสอบอัด/เล่นในแอปปลายทาง

## ขอบเขตปัจจุบัน

- ใช้ตำแหน่งหน้าจอแบบ absolute ควรใช้ความละเอียด การจัดจอ และตำแหน่งหน้าต่างแบบเดียวกับตอนอัด
- รองรับคีย์บอร์ด เมาส์ซ้าย/ขวา/กลาง และล้อแนวตั้ง ยังไม่มีปุ่มเมาส์ด้านข้างหรือล้อแนวนอน
- ยังไม่มี pause/resume, ตัวแก้ event หรือการรอภาพ/หน้าต่าง
- ช่วงว่างก่อน event แรกถูกเก็บไว้ตาม recording; ช่วงว่างหลัง event สุดท้ายก่อนหยุดอัดไม่ถูกเก็บ ใช้พักระหว่างรอบเพิ่มได้
- การ force kill process จะข้ามขั้นตอน cleanup; ควรหยุดด้วย F11 แล้วปิดตามปกติ

หาก `tkinter` แจ้ง `Can't find a usable init.tcl` ใน terminal ปกติ ให้ซ่อมการติดตั้ง Python พร้อมส่วน Tcl/Tk
ใน sandbox ของเครื่องมือนี้พบข้อจำกัดการอ่าน Tcl/Tk แต่ทดสอบหน้าต่างนอก sandbox ได้ โดยไม่ได้แก้ environment ของเครื่อง

## Build ไฟล์ .exe

ใช้ [PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html) แพ็กเป็นไฟล์เดียวแบบ windowed
การ build ต้องใช้ Windows และ Python พร้อม Tcl/Tk แต่เครื่องที่เปิด `.exe` ไม่ต้องติดตั้ง Python

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_exe.ps1
```

Execution policy ข้างต้นมีผลเฉพาะ process ที่รันคำสั่ง ไม่ได้เปลี่ยนนโยบายของเครื่อง
สคริปต์สร้าง `.venv-build` ในโปรเจกต์ ติดตั้ง build tools จาก `requirements-build.txt` แล้วใช้ `MacroCore.spec`
ผลลัพธ์อยู่ที่ `dist\MacroCore.exe`; เมื่อแก้ source ต้อง build ใหม่เพื่อให้ `.exe` มีโค้ดล่าสุด
`build` และ `.venv-build` เป็นไฟล์ช่วย build ไม่ต้องส่งไปพร้อม `.exe`

ผลตรวจ GUI รุ่นกะทัดรัดล่าสุด (15 ตุลาคม 2026, Asia/Bangkok):

- หน้าต่างหลัก 411×265 พิกเซล และแถบสถานะ 269×47 พิกเซล บนเครื่องทดสอบ; ขนาดขึ้นกับฟอนต์และ DPI
- เพิ่ม regression สำหรับการย่อหน้าต่าง ปิดหน้าต่างเสริมก่อนอัด ซ่อน HUD เมื่อหยุด โหมดซ่อนทั้งหมด และ Win32 styles ของ HUD; รวม 31 กรณีผ่าน
- ตรวจแถบสถานะที่แสดงจริงด้วย Windows hit testing: จุดกึ่งกลางแถบชี้ไปยังหน้าต่างด้านหลัง และ foreground window ตรงกับก่อนแสดงแถบ โดยไม่ติดตั้ง hooks หรือฉีด input ในการตรวจนี้
- build `.exe` ใหม่ขนาด 11,718,673 bytes และตรวจจากโฟลเดอร์ว่างโดยไม่มี Python ใน PATH ผ่านในประมาณ 2.03 วินาที รวมเริ่มและปิด
- self-test ของ `.exe` ยืนยัน GUI พร้อม, settings เริ่มซ่อน, HUD มี click-through/non-activating styles และติดตั้ง/ถอด hooks ได้
- ยังไม่ได้ทดสอบอัด/เล่น input จริงกับแอปปลายทางหรือทดสอบบน Windows เครื่องอื่น

แถบสถานะใช้ [layered window และ WS_EX_TRANSPARENT ของ Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)
ร่วมกับ NOACTIVATE/TOOLWINDOW เพื่อไม่บังคลิกหรือขึ้นใน Alt+Tab

ประวัติการตรวจ build รุ่นแรก (15 ตุลาคม 2026, Asia/Bangkok):

- สร้างด้วย Python 3.14.2 / PyInstaller 6.22.3 บน Windows 11 x64 ขนาด `.exe` 11,712,592 bytes (ประมาณ 11.7 MB)
- ชุดทดสอบเดิม 25 กรณีผ่านหลังปรับ startup และเพิ่มโหมด self-test
- ตัว `.exe` สร้าง GUI แบบซ่อน โหลด Tcl/Tk 8.6.15 และติดตั้ง/ถอด Win32 hooks ได้ โดยไม่เริ่มอัดหรือส่ง input
- ตรวจจาก working directory ว่าง พร้อมตัด Python ออกจาก PATH และนำ PYTHONHOME/PYTHONPATH/TCL_LIBRARY/TK_LIBRARY ออกจาก environment เฉพาะ process ทดสอบ; ใช้เวลาประมาณ 2.22 วินาที รวมเริ่มและปิด
- เครื่องมือตรวจ UI Windows เชื่อมต่อไม่ได้ จึงยังไม่ได้ตรวจหน้าต่าง `.exe` ด้วย screenshot หรือกดปุ่มผ่าน desktop automation
- ยังไม่ได้ทดสอบบนเครื่อง Windows เครื่องอื่น หรืออัด/เล่น input จริงจาก `.exe`

โหมดตรวจ startup สำหรับผู้พัฒนา (ซ่อนหน้าต่าง เขียนรายงานแล้วปิดเอง):

```powershell
.\dist\MacroCore.exe --self-test "$env:TEMP\MacroCore-self-test.json"
```

คำสั่งนี้สร้างรายงานในโฟลเดอร์ TEMP ของผู้ใช้ จึงใช้ได้แม้ลบโฟลเดอร์ `build` ไปแล้ว

## การเก็บไฟล์ในโปรเจกต์

ทำความสะอาดเมื่อ 15 ตุลาคม 2026 (Asia/Bangkok): ลบ `build`, `.venv-build`, `__pycache__`
และ `drift_log.csv` ที่สร้างใหม่ได้ รวม 41,747,162 bytes (ประมาณ 41.7 MB)
รายงาน self-test จาก build ก่อนหน้าถูกลบพร้อมไฟล์ชั่วคราว โดยเก็บผลตรวจไว้ในหัวข้อ build ด้านบน
ตรวจ SHA256 ของ `dist\MacroCore.exe` แล้วตรงกับก่อนทำความสะอาด

เก็บ source, ชุดทดสอบ, คู่มือ, ไฟล์ build และ `dist\MacroCore.exe` ล่าสุด พร้อม `macro.json` ที่อัดไว้
การ build ครั้งถัดไปจะสร้าง `.venv-build` และดาวน์โหลด build tools ใหม่ ส่วน drift log จะสร้างเมื่อมีการเล่นมาโคร
หลัง build รุ่น GUI กะทัดรัด ได้ลบ `build`, `.venv-build` และ `__pycache__` อีกครั้ง พร้อมตรวจ SHA256 ว่า `.exe` ล่าสุดยังตรงเดิม
